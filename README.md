# Wikilink Graph Retrieval

Retrieve the correct Wikipedia page for a hyperlink mention (a "wikilink") given only local anchor/context text, and test whether adding Wikipedia's link graph helps a dense bi-encoder beyond a strong lexical baseline.

This repo includes an end-to-end smoke run (synthetic toy data) and a "full" configuration wired to Wikimedia dumps.

## Problem Statement

Given a query context `query_text` extracted around a wikilink on a source page, retrieve the linked target page `doc_id` from a candidate corpus of pages.

Implemented objective and metrics:
- Retrieval models output embeddings and score candidates by dot product (`q @ d.T`).
- Evaluate on held-out source pages with `Recall@{1,10,100}`, `MRR@100`, `nDCG@100` (`src/wikilink_graph_retrieval/metrics.py`).
- Report top-1 calibration via ECE computed from an approximate softmax over retrieved top-k scores (`src/wikilink_graph_retrieval/eval_dense.py`).

## Dataset Provenance

Two data sources exist; the included results are from the toy dataset.

1. **Toy smoke dataset** (`configs/smoke.yaml`, generated by `src/wikilink_graph_retrieval/data/toy.py`)
- Deterministic synthetic corpus: `num_docs=300`, `num_edges=1200`.
- Link instances: `train_links=2000`, `val_links=300`, `test_links=300`.
- Page-level split by `source_page_id` (hold out entire "source pages" for val/test).
- Each target doc contains a unique identifier token (`uniq`) so the task is learnable without external pretrained models.

2. **Wikimedia dumps (English Wikipedia)** (`configs/full.yaml`, extracted by `src/wikilink_graph_retrieval/data/wikidump_extract.py`)
- Downloads from Wikimedia "latest" endpoints:
  - `https://dumps.wikimedia.org/enwiki/latest/enwiki-latest-pages-articles.xml.bz2`
  - `https://dumps.wikimedia.org/enwiki/latest/enwiki-latest-pagelinks.sql.gz`
- Downloader verifies an `<url>.md5` sidecar when available (`src/wikilink_graph_retrieval/data/download.py`).
- Extraction (baseline) keeps the top `top_targets` titles by in-link frequency and writes:
  - `target_pages.parquet` (title + first ~4000 chars of text as "lead")
  - `train_links.parquet` / `val_links.parquet` / `test_links.parquet` (page-level hash split by `page_id`)
  - `pagelinks_edges.parquet` (see limitations: current edge construction is a placeholder)

## Methodology (As Implemented)

**Sparse baseline** (`sparse_tfidf`)
- TF-IDF over `target_pages.text` with 1-2 grams, `min_df=2`, `max_df=0.95` (`src/wikilink_graph_retrieval/sparse_tfidf.py`).

**Dense retrieval** (`dense_text_only`, `dense_text_graph`)
- Tokenization: deterministic regex tokens hashed into a fixed vocab via BLAKE2b, with a learned `[CLS]` embedding at position 0 (`src/wikilink_graph_retrieval/tokenizer.py`).
- Encoders: separate query/doc Transformer encoders (`nn.TransformerEncoder`) with learned positional embeddings; representation is the `[CLS]` state projected to `embed_dim` (`src/wikilink_graph_retrieval/models/text_encoder.py`).
- Training loss: in-batch contrastive cross entropy over the similarity matrix (`src/wikilink_graph_retrieval/models/dense_retriever.py` via `train_dense.py`).

**Graph augmentation** (`dense_text_graph`)
- Learn node embeddings with a GraphSAGE-style neighbor-mean aggregator trained by link prediction with negative sampling (`src/wikilink_graph_retrieval/models/graphsage.py`, `src/wikilink_graph_retrieval/train_graph.py`).
- Fuse doc text embedding with doc node embedding using query-independent gated residual fusion:
  - `doc = text + sigmoid(MLP([text; proj(graph)])) * proj(graph)` (`src/wikilink_graph_retrieval/models/fusion.py`)
- For convenience, this baseline requires `graph.dim == dense.embed_dim` and indexes graph embeddings by `doc_id` (`src/wikilink_graph_retrieval/pipeline/train.py`, `src/wikilink_graph_retrieval/eval_dense.py`).

## Baselines and Ablations

Configured in `configs/smoke.yaml` and `configs/full.yaml`:
- `sparse_tfidf`: lexical retrieval baseline.
- `dense_text_only`: dense bi-encoder ablation with `use_graph: false`, `fusion: none`.
- `dense_text_graph`: main model with `use_graph: true`, `fusion: gated_residual` (initialized from the text-only checkpoint when present).

## Reproduction

Primary commands (repo-local venv; never install into system Python):

```bash
make setup
make all
```

By default, `make all` runs with `CONFIG=configs/smoke.yaml` (see `Makefile`).

Expected outputs:
- `artifacts/results.json`
- `artifacts/report.md`

Run tests:

```bash
.venv/bin/pytest -q
```

Run the Wikimedia-dump configuration (large downloads; disk/CPU heavy):

```bash
make all CONFIG=configs/full.yaml
```

## Limitations (Current Code)

These matter if you intend to treat `configs/full.yaml` as a faithful Wikipedia experiment:
- `src/wikilink_graph_retrieval/data/wikidump_extract.py` does **not** currently build true pagelinks edges using `pl_from -> pl_title`; it writes a placeholder edge set built from popularity ordering (explicitly documented in-code).
- Wikilink parsing is naive (`[[Target]]` / `[[Target|anchor]]`) and does not implement full MediaWiki parsing (templates, nested markup, redirects, etc.).
- The wikidump context window is character-based (fixed ±400 chars) and ignores `context_window_tokens` in the config.
- The toy dataset also ignores `context_window_tokens` (it is recorded in `meta.json` but not enforced when generating `query_text`).
- Dense retrieval uses a hash tokenizer and randomly initialized Transformers; results are not comparable to modern pretrained retrievers.
- Evaluation uses exact top-k dot product search; scaling to millions of docs will require ANN indexing and careful batching.
- Graph embeddings are indexed by `doc_id` and assume alignment between `doc_id` values and corpus rows.
- Throughput numbers (`docs/sec`, `queries/sec`) are hardware-dependent and come from timing only embedding and exact search in `eval_dense.py`.

## Next Research Steps

Concrete engineering steps to make the "full" setup a credible research baseline:
1. Implement faithful graph extraction: build `page_id -> doc_id` mapping and construct edges directly from `pagelinks.sql.gz` (`pl_from` to resolved `pl_title`), including redirect resolution.
2. Replace the hash tokenizer + randomly initialized encoders with a pretrained text encoder (e.g., DPR/Contriever family) and proper subword tokenization.
3. Add ANN retrieval (FAISS/HNSW) and evaluate recall/latency tradeoffs at large `top_targets`.
4. Improve training data: hard negatives (BM25 mining), multi-positive targets, and better context extraction (strip markup, handle sections).
5. Strengthen baselines: BM25, hybrid sparse+dense, and a second-stage cross-encoder reranker for top-100.
6. Add experiment tracking: fixed hardware metadata, run-to-run variance, and larger ablation grid (fusion methods, graph neighbors, graph dim).
